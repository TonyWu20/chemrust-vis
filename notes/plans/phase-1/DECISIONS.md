## Architectural Decisions

### A1: Feature-gated CASTEP loader

The CASTEP `.cell` loader lives behind a cargo feature `castep-loader` in `chemrust-vis-core`.
This keeps the core crate compilable without the `castep-cell-io` + `castep-cell-fmt` dependency
chain. The TUI binary enables this feature.

### A2: Scene is renderer-agnostic

The `Scene` struct produces abstract draw commands (points with colors, line segments) that any
rendering backend can consume. The ratatui canvas rendering is one such backend. This allows
future renderers (sixel, SVG export) to consume the same scene data without changes.

### A3: nalgebra-only math

All 3D math uses `nalgebra` 0.33 (same version as chemrust-geometry). No `glam` or other math
library. `Isometry3` for view transform, custom orthographic projection matrix since nalgebra
0.33's `Orthographic3` was deprecated.

### A4: Camera uses spherical coordinates

Spherical coordinates (θ azimuthal, φ polar, r radius) around a target point. This is the most
natural parameterization for orbit controls. The view matrix is computed as
`Isometry3::look_at_rh(&pos, &target, &up)`.
